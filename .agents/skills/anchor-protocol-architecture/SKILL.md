# Anchor 协议翻译架构

以协议层独立承载转换语义，让新增协议或字段主要修改协议适配器及其测试，避免继续向网关调度代码添加协议分支。本规范覆盖现有 OpenAI Responses、Chat Completions、Anthropic Messages，不授权新增外部协议、独立服务、依赖或发布。

## 开工与同步维护

- 先读取[当前翻译层契约](../../../docs/design/protocol-translation.md)，按范围读取[Chat 桥接支持表](../../../docs/design/protocol-chat-bridge.md)与实际代码；不要机械套用旧文件结构或把规划当成实现。
- 开始实现前简述现状、边界及增量迁移步骤。复用现有转换规则，允许旧入口委托新层，不长期维护两套独立规则，也不为统一形式重写整个网关。
- 改变相关架构原则、模块职责、公共接口、状态生命周期、兼容／降级策略或恢复边界时，**在同一任务同步更新本 skill、适用设计契约、实现和测试**。仅内部实现变化且不影响这些约束时，核对一致性即可，不为留痕改写规范。
- 发现规范与实现冲突时，说明差异及兼容影响，依据任务授权修正；不能借重构暗改默认行为。设计文档维护当前模块、支持范围、限制和例外，本 skill 维护后续工作的决策约束。

## 模块边界

调用方向：客户端请求 → Session 解析／校验 → 网关选候选 → Prepare 创建 Attempt → 网关发送 → 同一 Attempt 还原普通／流式响应 → 网关交付与持久化。

| 归属 | 负责 | 不应承担 |
| --- | --- | --- |
| 协议层 | 结构／能力校验、上游编码、响应与 SSE 解析编码、工具身份和命名空间、调用 ID、custom 包装、思考与正文、用量和结束语义、安全诊断 | 渠道选择、鉴权凭据、网络请求、重试决策、数据库、客户端工具执行 |
| 网关 | 客户端鉴权与访问范围、模型／供应商／Key 选择、上游认证与网络、超时取消及连接、候选和恢复预算、HTTP 交付控制、日志用量费用持久化 | 参数改名、工具展平与还原、custom 解包、事件对应、协议结束状态或用量结构转换 |

- 协议库不依赖 `core`、`state`、`logbook` 或全局可变状态。核心转换可使用 `io.Reader`／`io.Writer` 与 context；HTTP 期限和 flush 适配留在薄边界中。
- 模型来源排序属于核心调度：逐 Key 排序身份使用供应商／上游模型／Key，保存与实际派发须一致；不得将这种排序状态或选择规则放进协议 Session／Attempt。
- 网关只消费协议无关的准备结果、响应和诊断，不获取 `ChatMapping` 等协议专属映射并自行决定如何使用。
- 当前入口是 `protocol.NewSession`、`Session.Prepare`、`Attempt.TranslateResponse/TranslateStream`；具体文件归属见设计契约，不把这些名字固化为禁止演进的接口。

## 请求与尝试生命周期

- Session 保存复制后的原始客户端协议、原生请求和未污染基线；可并发准备独立 Attempt。每次候选选择都重新 Prepare，不沿用失败候选的可变状态。
- Attempt 由一次上游尝试独占；编码请求与返回路径共用该尝试的私有工具映射，映射不得跨请求共享。暴露的请求体、策略投影和诊断集合应为副本或不可变值。
- 下一轮工具结果通过客户端声明、历史调用、name／namespace／call_id 重建身份，不依赖上一次 HTTP 请求残留的进程状态；长名称、碰撞和歧义必须有确定规则或明确拒绝。
- 取消、失败和重试结束应释放请求状态；网关拥有连接并负责 cancel／Close。协议层不接管调用者 reader/writer 的关闭责任，不引入请求状态注册表。
- 历史恢复创建派生 Session，不修改原始基线或污染其他候选。是否再次发送及其预算始终由网关决定。

## 语义表示、原生路径与上游特性

- 公共语义使用明确类型，区分思考、正文、函数／custom 调用、工具结果、用量、结束原因和完成状态。复用现有 RequestInfo、Capabilities、Usage、Observation、Diagnostics、Result/Item 等类型，不继续扩大任意 map 的职责。
- 内部表示不能成为静默丢能力的最小公共子集。当前 Responses 形状请求桥可增量复用；`PolicyFields` 仅为旧日志／亲和性逻辑的策略投影，不是通用语义模型或原生发送体。
- 同协议保留受控原生路径及原生字段，不强制往返其他协议。仍执行鉴权、无状态、工具执行范围、能力校验和生命周期限制；顶层 tools 与 inline additional_tools 同样检查。
- 原生路径允许设计契约明确列出的规范化，如路由 model／service_tier、Responses store=false、Anthropic 缺省 max_tokens；不得据此任意过滤字段。原生保留签名思考或多模态不代表跨协议支持。
- 协议请求头只通过类型化非秘密元数据进入 Prepare，由协议层返回固定名单及副本；网关机械写入，不转发客户端认证或任意头。当前仅 Anthropic → Anthropic 保留 anthropic-version/重复 anthropic-beta；跨协议隔离，缺省版本沿用认证层默认。新增头/方向必须同步契约及认证隔离测试，不能从 beta 名称推断已支持能力。
- 协议标准映射与供应商特性分开。不得按供应商或模型名称猜测 thinking、预算或 Token 字段；特殊行为须有已验证的显式能力配置及针对性测试，由适配器消费。
- OpenAI 兼容用量统一采用“输出含推理”的内部口径。Responses／Chat 仅在合法整数 total_tokens 严格等于输入＋原始输出＋正数 reasoning_tokens 时，将独立推理计入输出；这是已验证的 xAI 结构兼容规则，不依赖名称或新增供应商开关。总数缺失、非法或不满足完整等式时不得按差额猜测／补齐；已有包含式用量不重复相加，reasoning 仍大于输出时保持未知。普通回包、SSE、探测及日志复用 ReadUsage，原生 JSON／SSE 不重写，Anthropic 的缓存用量口径不变。

## 兼容与恢复

- 明确报告 Full／Degraded／Unsupported：完整承载、保证发生变化、无法可靠表示。不能为了发出请求而静默删除未知字段、历史思考、工具或约束；保留既有错误码和默认降级策略。
- Responses／Chat → Messages 请求先由协议适配器校验选项：普通 text 格式、disabled truncation 与空 reasoning 历史可规范化；effort=none 明确映射 thinking.type=disabled，其他强度不猜测预算。仅字符串 client_metadata、已知 sequential_cutoff 传输选项、reasoning summary 样式及可选密文返回投影可按既有安全类别显式降级；未知字段、格式／强度要求、非空明文推理历史与非空密文继续准确拒绝，不能冒充正文错误。此入口不更改原生保留、Session 基线、候选或恢复预算。
- 当前允许的 Responses → Chat 降级为 reasoning_summary_style、encrypted_reasoning_projection、custom_grammar_description；Messages 目标复用 custom_grammar_description，并按上一条处理请求选项。Messages 入口跨协议允许经过校验的缓存提示降级 prompt_cache_control、工具错误标志文本化 tool_result_error_text；Messages 返回明文 thinking 允许以 anthropic_thinking_plaintext 降级成独立推理内容，签名不得标为 OpenAI 密文，不承诺思考历史往返。具体语义以支持表为准。grammar 文字描述不保留原生强制语法约束；可选密文输出投影的降级不允许丢弃非空历史密文。
- Messages 与 Chat 目标复用同一请求局部 namespace／custom 工具索引；不得维护另一套命名、历史重建和返回还原规则。Messages 原生 type=custom 仅代表客户端执行函数，不扩大到托管工具。
- 密文不可解密时不伪造明文，不将思考作为正文。非空密文历史不能跨协议转换时必须拒绝；多模态、tool_search、签名思考等仅按已验证方向声明支持。
- 保留明确的原生 Responses 密文拒绝恢复：未向客户端交付、同渠道至多一次、原期限内，由派生 Session 清理历史 reasoning，明确记录有损语义，不扩大触发或重试预算。
- 区分已实现的原生预清理：仅派发副本中 input 顶层 reasoning 的 encrypted_content 显式为 null、非字符串或空串时删除该字段及该项 id；保留条目、summary、其他字段与非空密文，缺失字段不改。此操作不修改客户端历史、不额外请求、不消耗恢复预算、不记为拒绝后恢复。变更此例外须同步契约与保留边界测试。
- 目标 Responses 的派发副本允许规范化 input 顶层工具项 ID：function_call／custom_tool_call／custom_tool_call_output 的非空字符串 id 分别要求 fc／ctc／ctco 前缀，缺失时补前缀；超过64字符或与已有ID碰撞时确定性散列缩短／消歧。只改 id，不改 call_id、工具内容、非工具项、客户端历史或原生响应；不生成缺失ID、不修复非字符串ID、不删除推理项、不增加请求或恢复预算。规则留在协议层，并验证幂等、碰撞、候选隔离及工具结果回传闭环。
- 推理响应头等待与正文共用供应商总期限；允许供应商显式设置首字期限，网关拥有独立计时及取消，协议层只通知首个实际生成内容。正文、思考、工具参数或音频内容可满足首字；响应头、角色声明、心跳与空生命周期事件不能满足。首字到达只停止首字计时，不停止总期限；路径修复/同渠道密文恢复共享两类原期限。首字超时不重放；SSE 已提交后用协议层固定本地错误事件结束，不能合成成功或改写已取得上游HTTP。缺版本基址只有明确 HTML 且 200/404/405 时允许同源补 /v1 一次；成功的 JSON/SSE 类型可按基址、协议、凭据摘要有界短期复用，不写配置，不将类型检查冒充语义成功。缓存失效的当前请求不重放；下一独立请求重新识别，具体上限见契约。
- HTTP 200 或传输结束不代表生成完整成功；用量未知与明确为零必须区分，不能编造完成状态或用量。
- 首字通知须覆盖已知生成内容的增量与完整项／part／done 快照（包括非空推理密文），不能只认 delta。Responses／Anthropic 的 JSON 缺失 type 时可用 SSE event 名解释，显式 JSON type 优先；原生转发保留原事件和载荷，不为兼容而重写内容。空容器、ID、状态与未知元数据不满足首字；识别通知不改变既有正文／有效输出计时指标，也不扩大跨协议内容支持。网关应在发送本地超时错误帧前固定超时原因，避免客户端收到错误后断开将已确认首字超时覆盖为客户端取消。

## 流式与资源边界

- 文本和可增量转换的参数边收边交付，不读完整回答后伪装流式。保持工具 ID、output_index 和事件顺序；正确处理参数分片、转义及 Unicode。
- 仅对无法可靠增量解码的内容有界缓冲，如 custom 包装完整校验后的解包和 Anthropic 并行交错块。顺序块应在源项结束后推进，不等整份回答完成。
- 单事件、累计输入、转换内容、工具／输出项数量及普通响应读取均须有明确上限；当前数值见设计契约。修改上限同步文档和边界测试，不引入无界队列或无必要后台 goroutine。
- Messages 跨协议流须校验 message_start、块索引／类型／关闭及 message_delta 的有效结束原因；无参数增量时在块关闭回退开始帧 input，不能丢掉非空对象。原生与转换流逐字段合并 usage，保留未被后帧覆盖的缓存用量；不据此重写原生事件。
- 缺少必要终止事件、非法结束原因、参数截断、断流、取消、超限或写失败时，不得合成成功完成事件。已完整写出的完成帧保留完成事实；写失败不能记成功。
- 开始向客户端输出后不得重新请求上游并拼接另一份回答。阻塞读由网关取消网络请求／关闭响应体解除；同步转换无需另加读写协程。已有恢复检查的单次待决读不应被误写为完全无协程。

## 诊断与验证

- 协议层返回固定、安全的客户端／目标协议、request／response／stream 阶段、错误类别、兼容性及降级事实；网关补充实际上游派发和客户端交付状态并持久化。
- 网关可记录目录内错误身份、固定传输原因/阶段和供应商期限；有界读取最多16 KiB上游错误并完整还原响应体，协议层 ClassifyUpstreamError 将 code/type 映射为固定类别。推理强度拒绝仅按已知 unsupported_value/invalid_value 与固定 effort 参数路径，或完整已知错误模板及白名单强度枚举识别为 unsupported_reasoning_effort；参数路径、模型名及 message 均不入日志。不得根据此诊断自动改强度或重放，未知内容不入日志。
- 不记录原始正文、提示词、思考、工具参数、凭据、任意用户字段名或未经处理的上游错误；包装错误也不能展开这些信息。外部错误或配置契约确需改变时，遵循适用 CLI 文档规则同步契约。
- 按影响范围选择测试，覆盖已支持组合及拒绝边界、原生保留、普通／流式、思考正文分离、输出格式、工具定义与结果、namespace／custom／并行、长名碰撞歧义；工具变更验证定义 → 调用 → 客户端结果回传 → 最终答案的完整闭环。
- 生命周期改动验证并发请求、候选切换、恢复隔离和取消清理；流式改动验证提前交付、参数截断、终止、上限、写失败及输出后不重放；诊断改动验证未知／零用量、阶段和脱敏。
- 复用 `internal/protocol/session_test.go`、`chat_bridge_test.go`、`native_reasoning_test.go` 及 `internal/core/translation_gateway_test.go`、`encrypted_context_test.go`；使用隔离状态与模拟 HTTP 上游，不修改真实 Agent 配置或调用付费上游。
- 遵守仓库资源保护、任务记录与 Git 规则；重测试串行有界。其他未提交改动导致失败时区分归属，必要时隔离验证本轮补丁，不使用 stash／reset 隐藏其他工作。不因架构任务自动打包、发布或替换运行版本。


## 网关会话亲和与重试

- 会话路由只用经过调用者归属校验的显式会话 ID；不得通过提示词、instructions 或首条输入相似度跨会话粘连。只有成功请求建立会话渠道亲和。
- 会话保持成功渠道，直到它没有可用 Key 或供应商无法调度；此时按当前模型顺序 fallback。新会话从当前顺序开始。亲和不等于上游缓存命中承诺，并需有界保存。
- Key 冷却只排除对应 Key。冷却到期直接回到可用池；不要求半开探测或独占预约。
- 连接前传输失败及明确上游错误可由网关继续候选；连接后结果不确定、已交付客户端的流式响应不得重放。所有候选耗尽须返回清晰的不可用错误。

## 应用监听与调用者凭据

- 独立应用 API 监听、LAN 来源准入及普通 gateway Key 身份属于网关／管理层，契约见 `docs/design/api-service.md`；协议层不接触监听设置或调用者秘密。
- 默认关闭的应用监听可按显式配置开放私有 IPv4 LAN，管理与托管 Agent 监听继续回环；运行策略采用启动快照，保存待重启设置不提前放开准入。Origin防护、权限隔离和上游认证隔离保持。
- 普通 Access 的日志身份为 `access_key/access_label`，上游 Key 和托管 Binding 仍是不同身份；不从客户端自报头推断，不记录完整调用令牌。
