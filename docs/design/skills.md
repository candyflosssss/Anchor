# Skill 中心库与固定版本挂载

- 状态：2026-10-22 项目自动发现已随 [desktop.68 dev](../release/desktop.md#skill-project-discovery-68) 发布，核心、CLI 与页面同步；既有自动收录／原件清理已随 desktop.65 发布。本轮仅在线投放，未自动安装。
- 命令唯一入口：[CLI 大全](../cli/commands.md#14-skill-中心库)。
- 2026-10-23 桌面表达调整（已随 [desktop.71 dev](../release/desktop.md#model-glass-71) 发布）：按“我的 Skill”和“文件位置”组织，不再将中心库／来源／挂载作为页面分类。存储及 CLI 契约不变。

## 1. 自动收录，原件保留

核心启动后在后台收录一次，运行期间每分钟检查新来源；首次打开 Skills 或执行 `scan/list` 也立即收录。发现可读取的新 Skill 后，将完整文件内容复制到 Anchor 状态目录 `skills/library/<skill-id>/vN`。自动收录只写 Anchor 库，不删除、移动、改写外部原件，也不改变原件权限；不手动清理也能照常使用。单项失败继续处理后续来源，下次扫描重试。

新 Skill 直接创建在库中，按需另选作用域与固定版本安装。已收录来源的后续编辑仍显示差异，由用户明确导入修订，避免后台覆盖库中的编辑。

手动「清理原件」／`cleanup`：携带来源 ID、最新内容摘要和库 revision，先复制并从磁盘核验原件当前内容，再把原位置替换为指向该快照的固定版本软链接。原位置若已经是外部软链接，只替换这个链接，真实目标保留。清理后作为受管挂载显示；不自动升级其版本。普通安装仍只向空位置创建链接，不接管已有文件。

## 2. 身份、版本、来源、挂载分离

- Skill ID：随机稳定身份；同一真实目录的多个入口归入同一身份；同名且全树摘要相同的副本也复用已有身份与版本，内容不同则分别保留。CLI 可在尚未关联的来源上用 `--skill` 指定已有身份；已关联来源不允许静默换身份。
- Version：每个 Skill 的不可变 v1、v2…完整文件快照，记录父版本、来源基线、创建时间、来源类型、文件清单与摘要。全树摘要包含相对路径、文件字节哈希、长度及本平台可执行位，而非仅比较 `SKILL.md`。
- Source：原始目录路径与最近一次成功导入的版本号。新来源自动归档；已关联来源变化不自动保存版本，需明确导入修订或清理时归档当前内容。相同摘要复用已有版本，可能复用历史版本，不承诺每次操作都递增版本号。
- Mount：目标作用域、路径、Skill ID、固定版本和精确软链接目标。不使用可变 `current` 链接；保存新版本不改变任何现有挂载。更新／回滚均针对单个挂载显式确认。

来源以最近导入基线 B、当前来源 S、库最新版 L 判定：

| 条件 | 状态 | 默认行为 |
| --- | --- | --- |
| 新来源 | local | 自动复制归档，原件保留 |
| 已手动删除库记录 | excluded | 暂停该原位置自动收录，可手动重新导入 |
| S = L | in_sync | 内容一致，导入复用快照 |
| S ≠ B，L = B | source_changed | 待导入变化，不自动版本化 |
| S = B，L ≠ B | library_changed | 库有不同版本，不回写来源 |
| S ≠ B，L ≠ B，S ≠ L | diverged | 双方分歧，明确导入保存来源快照，不自动合并 |

差异按文件列出新增／删除／修改，包含可执行位变化。文本是变更前后并排预览，不是行级合并器；二进制只标记变化。默认来源比较导入基线，也可选库版本比较；库版本默认展示与父版本差异。没有三方合并、分支发布、SemVer 或批量自动升级。

## 3. 发现范围与限制

不是全盘扫描，也不承诺发现所有已安装 Agent 和所有项目：

- 全局：共享 `~/.agents/skills`；有配置目录证据时读取默认及配置的 Codex、Claude Skill 目录，以及已知 Gemini、OpenCode 全局位置。目录证据不等于可执行程序已安装，与模型网关托管登记无关。
- 项目默认自动发现，不要求手动登记，也不依赖 Codex 索引存在。逐个检查用户主目录下 `Projects`、`projects`、`Code`、`code`、`src`、`repos`、`Repositories`、`Work`、`work`、`Workspace`、`workspace`、`workspaces`、`Documents/GitHub`、`source/repos` 的**直接子目录**；以 `.git`（含 worktree 指针文件）或已知 Agent 目录为项目证据。只检查项目的 `.agents/skills`、`.claude/skills`、`.codex/skills`、`.gemini/skills`、`.opencode/skills`，不进入项目内容、依赖、隐藏子目录或更深层项目。
- 继续合并有界只读 Codex `.codex-global-state.json` 已保存／排序工作区根及用户补充的绝对项目路径。已归档来源／挂载也保留原项目路径，工作区索引消失不会让已知项目失联。有效项目表每次扫描重建；索引 `projects` 字段只记录手动补充路径，为空不再代表未发现项目。通过软链接真实路径去重自动候选；已有来源或明确登记的别名仍保留，方便核对／手动清理；重复 Skill 入口继续复用库身份，不重复存快照。
- 不读取聊天正文、凭据或任意 Agent 配置内容；不猜测 Claude 编码项目名，不包含未经核实的 DSH Skill 布局。未知位置可登记项目，未来以适配器增补。
- Codex `.system` 内置 Skill 也收录。外部目录及内部资源软链接均跟随读取，库快照保存独立文件，不依赖原链接；循环／损坏链接报错。已有 Anchor 挂载单列，缺失／冲突只报告，不自动重建。
- 有效项目表上限1024，手动补充项目仍最多64；常见容器每轮总计最多检查4096个直接目录项，Codex 工作区索引最多1 MiB。达到发现边界返回 `project_limit`／`project_search_limit`，无法读取某个容器返回 `unreadable_project_search:<id>`，不冒充全量扫描完成，单个容器失败不阻断其他容器；扫描响应支持取消。
- 库身份、来源关联、受管挂载及单作用域目录项分别最多4096，每 Skill 最多64版本。单树最多4096普通文件、8192含目录条目、64 MiB内容、64层深度；逐项处理，没有共享哈希额度，也不因失败树扣除后续读取额度。索引最大32 MiB，Skill客户端响应独立64 MiB，其他接口不变。
- 支持中文、空格及可移植文件名，每段最多255 UTF-8字节，相对路径最多512字节、绝对根最多1024字节。拒绝遍历、控制字符、Windows保留名、大小写冲突和特殊文件。外部原件按当前账户的实际读取权限处理，普通组写权限和硬链接不再拦截；Anchor私有索引与快照仍严格校验权限、所有权和链接。
- 空目录不进入文件快照；可编辑 UTF-8 文本每文件48 KiB，二进制完整复制但不在线编辑。管理请求仍受128 KiB JSON正文限制，多文件请求还受总正文限制。差异每侧每文件4 KiB、总文本128 KiB，截断显式提示。

## 4. 写入、安全和恢复

统一路径：前端 Model → 受控 Wails Bridge → `internal/client` → 管理 API → `internal/skills.Manager`；CLI 复用同一核心。端点为 GET `/control/v1/skills`、POST `/control/v1/skills/detail`（只读）与 POST `/control/v1/skills/action`。沿用 owner 授权、Origin 防护和实例校验；自动收录由核心负责，不需要逐项批准；GET workspace 可能初始化库并收录新来源，因此同样校验 owner 和实例身份。显式动作需 `approved=true` 和最新 workspace revision，导入与清理另需扫描／详情的来源 hash。远端 Context 的路径属于远端核心主机，非桌面本机。

核心互斥与系统文件锁保护写操作；快照暂存后发布，索引原子替换并同步。加载时校验索引身份、版本、文件摘要、关联、挂载目标与恢复日志；快照被外部篡改时拒绝读取／更新，不尝试覆盖修复。快照文件默认只读，但同账户仍可改权限，不能声称操作系统级不可篡改。

原件清理先写入恢复日志，在同一父目录暂存原件，核验其摘要后向空位置创建链接；链接和挂载索引同步成功后再次核验暂存原件，再删除这份已归档原件。链接创建失败会尝试恢复原件；任何外部变化或冲突都保留相关文件，拒绝覆盖。私有库本身及包含它的目录不得作为清理对象。

挂载写前保存 intent，更新时隔离旧链接，再只向空位置创建新链接。中断后扫描只提示，下一次明确批准的动作先核对恢复已批准的事务；恢复改变 revision，触发动作需刷新后重新确认。外部替代文件／链接不覆盖，冲突时保留日志及隔离链接；用户应先核对并自行移开冲突项，再刷新与明确操作。不要手动删除日志或把恢复解释为“扫描自动恢复”。尚无单独的恢复取消／孤立快照垃圾回收界面。

解除挂载只移除与记录目标精确匹配的受管链接；已缺失时仅移除记录；外部替代内容拒绝。库删除存在任何挂载记录时拒绝（包括缺失记录，需先解除），删除只移除索引及来源关联，保留磁盘快照作为恢复数据；来源路径进入自动收录排除表，避免立即重现，可手动导入恢复管理；不触碰原件。没有自动垃圾回收。

Windows 需系统允许软链接（开发者模式或相应权限）；失败报告 `skill_link_unavailable`，不自动退化成复制。Windows 不保留 POSIX 可执行位，摘要使用 false；Linux保留可执行位。跨平台本机原生 GUI／Agent 加载行为未验收，跨编译不能替代原生验证。

## 5. 桌面交互与验证分层

`features/skills/skill.model.ts` 校验规范生成 DTO，并从同一 workspace 投影文件位置与 Agent／项目名称；`use-skill-controller.ts` 管理读取生命周期、草稿、二次确认、并发写锁和结果未知；`skills.view.tsx` 展示“我的 Skill”和“文件位置”。切换设备通过 instance key 卸载并丢弃旧状态；写入期间阻止导航，失败只重读不自动重试。缺少真实绑定／旧核心报错，不回退 Mock。

“我的 Skill”按库身份列出一次，计数单位为“个”；每个 Skill 详情内直接合列原位置文件及 Anchor 快捷方式，展示 Agent／项目、完整路径、状态、保存／指定版本和操作。“文件位置”按来源与受管挂载的路径合计，单位为“处”，保留重复入口及已缺失记录，可按 Skill 筛选，并分别列出原位置文件／Anchor 快捷方式数量；不是又一组 Skill 数量。例：47条来源关联归属于36个Skill，7条挂载归属于其余4个Skill时，展示40个Skill、54处位置；不按40与47之差推算漏收。文件存在或链接正常不等于 Agent 已加载；外部原位置文件也可能经过已有软链接访问，不称为独立实文件。

原“安装到…”改为“添加到 Agent / 项目”，仍创建指定固定版本链接；原“清理原件”改为“改用 Anchor 副本”，确认明确先完整保存／核对、再删除此处已保存原文件并换快捷方式，已有软链接只替换链接且保留目标。原“导入修订”改为“保存此处改动”；一致来源不展示多余保存按钮。原“解除挂载”改为“移除快捷方式”，确认说明此处将不能再通过该链接读取Skill、不恢复独立文件且不删除 Anchor 保存内容。编辑、添加与换用副本均不暗示其他位置自动追随最新版，批量添加／批量替换原件尚未实现。底层动作、approval、revision、hash与CLI命令名称不变，不增加仅为改文案的CLI命令。

自动发现、按路径计数与快捷方式说明收进折叠“使用说明”，不堆常驻教学段落；错误、加载、扫描边界和不可读提示常显。“补充项目”只用于非常用位置，非首次使用前置步骤。页面继续支持创建、文本文件新版本编辑／新增／删除、差异和保存、补充项目、固定版本添加、单位置换版／回滚／移除快捷方式及库删除。将不同来源明确归入已有 Skill 暂由 CLI `import --skill` 提供，内容不同的同名来源不自动合并。

共享样例：`desktop/contract/skills.json`。隔离 Go 核心／CLI／桌面桥接测试、前端 Model 测试、浏览器模拟绑定和真实两平台原生验收分别记录；浏览器 Mock 成功不代表已验证真实 Agent 读取软链接。
