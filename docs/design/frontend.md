## 1. 文档职责与边界

总体产品范围以 [初版技术设计](architecture.md) 为准，现有实现以 [首个实施里程碑](implementation.md) 为准。本文规定界面技术与组织、前后端职责边界，以及 Linux / Windows 两端的统一体验。开发时同时遵循[项目级前端 skill](../../.agents/skills/anchor-frontend-architecture/SKILL.md)；该 skill 将本规范转为开发检查项，不另建一份视觉规范。

前端负责页面、组件、表单、导航、用户确认和状态展示，不负责模型代理、Agent 配置文件修改、SSH、隧道、凭据存储或实例连接策略。前端不因采用 Wails 而获得任意系统操作职责，也不在这里重定核心的语言、数据库或服务架构。

默认接入方向为：前端 Model → 类型化桌面接口 → Wails Go 薄适配层 → 现有 `internal/client` → 管理 API。CLI 与 GUI 复用核心业务规则，不以拼接 CLI 命令、直接操作数据库或放开任意 CORS 接入页面。Wails 适配层负责受控桌面能力与连接，不属于前端 MVC 的 Controller，也不复制核心业务。

本机宿主方法、错误、鉴权、超时与生命周期见[桌面运行契约](desktop-runtime.md)，供应商字段和密钥三态见[供应商接口语义](provider-interface.md)。规范源为 Go 桌面 DTO，生成 TypeScript，并用同一组合成样例核对 Go 与 Mock；真实调用链已经接入现有管理客户端。前端可以使用明确标注的模拟数据制作原型；模拟状态不等于真实功能已可用。管理凭据留在 Go 侧，供应商密钥仅用于必要的短暂输入与提交，不在前端持久保存或进入日志。

本轮安装交付补齐范围见[桌面安装打包](../release/desktop.md#1-安装与使用行为)：Windows 当前用户安装器、Ubuntu 24.04 AMD64 `.deb`，保留现有视觉与受控接口；用户明确跳过本轮验收，不取消后续公开发行门禁。

### 1.1 已确认的桌面启动与生命周期目标（2026-10-11）

**Windows 与 Linux 使用同一产品行为：安装桌面版后，用户双击应用入口直接打开 GUI，由 Go 桌面宿主自动启动或连接本机核心，不要求用户手动开终端、执行 init / serve 或运行前端开发服务器。** 这是已确认的正式桌面版目标，不是当前 CLI 包或供应商 Mock 原型的能力。

| 场景 | 规定行为 |
| --- | --- |
| 安装完成 | 提供可发现的应用入口；安装本身不默认启动核心、不注册系统服务、不启用开机自启动 |
| 首次打开 | 先显示界面骨架和启动状态；宿主在当前用户作用域安全初始化缺失状态，保留已有实例配置与权限保护，再启动核心；供应商等业务配置仍由用户填写 |
| 核心未运行 | 宿主自动启动独立于窗口的本机后台核心，不依赖保持终端打开；前端不执行 shell 命令 |
| 核心已运行 | 核验实例身份、API 兼容性与管理授权后连接复用；不按端口存在或残留 PID 文件判定可用，不另起重复核心 |
| 连续或并发打开 | 对同一状态目录用实例锁协调启动；锁竞争后重新探测并核验，不删除锁、不强杀占用进程；窗口单实例机制由宿主契约另定 |
| 尚未就绪或失败 | 显示启动中／已连接／启动失败／已断开及可执行的恢复说明；管理与写入仅在握手就绪后开放，失败不回退到 Mock、不覆盖配置、不无界重试 |
| 关闭窗口／退出界面 | 核心继续运行，不触发托管配置恢复；再次打开可以重新连接。不得将普通窗口关闭绑定成停服 |
| 显式停止核心 | 单独显示目标、连接来源与影响并要求确认；复用核心正常停服、在途请求处理及条件恢复，不用强杀替代。失败或结果未知不得显示已停止 |
| 非宿主创建的实例 | 可以在授权与身份核验后连接；不因退出界面而终止，不自动接管其服务管理方式；显式停止须另有批准的权限／停止契约 |
| 开机自启动 | 独立设置、默认关闭；启用／关闭需用户主动选择，明确启动对象与用户级作用域，不自动提权 |

自动启动仅针对当前用户的本机实例，不隐式启动远端核心、创建 SSH 隧道或修改真实 Agent 配置。已有用户批准的托管策略随核心正常启动执行；安装和首次打开不能制造新的托管授权。关闭界面后如何发现／重新打开入口可以按平台适配，系统托盘不是 Linux 的强制依赖。

桌面进程与独立核心的退出、日志管道、端口占用、崩溃、重启和升级行为须在宿主契约中落实；不能仅在开发环境放入后台就称为完成。开发版采用同一桌面二进制的独立 `--core` 子进程，核心与宿主分别使用生命周期；宿主关闭不会调用停服。已增加 `stop --approve` 与管理面正常停服接口；`serve` 本身仍是前台命令。已补齐 Windows 当前用户安装器与 Ubuntu24.04 AMD64 `.deb` 打包入口；用户级服务、托盘与开机自启动尚未实现，跨平台实际行为仍须原生验收（本轮依用户要求不执行）；实际 CLI 以[最新指令大全](../cli/commands.md)为准。

desktop.10 小步在既有供应商详情增加显式“获取模型目录”：Model 校验公开目录 DTO 与固定错误，hook Controller 管理一次请求、重复点击及过期结果，View 只展示限高列表、HTTP 与耗时。数据来自受限 Go 桥接，前端不直接访问上游。无推理测试、导入映射、余额或后台健康探测；契约见[供应商接口 §4](provider-interface.md)。

## 2. 技术选型

| 部分 | 方案 | 职责 |
| --- | --- | --- |
| 主要开发语言 | TypeScript，启用严格类型检查 | 页面、组件、交互与前端状态 |
| UI 框架 | React | 组织页面和可复用组件 |
| 基础组件 | shadcn/ui | 按需引入按钮、输入框、菜单、弹窗、表格等组件源码 |
| 样式 | Tailwind CSS + CSS 主题变量 | 布局、响应式、统一颜色 / 间距 / 圆角 |
| 前端构建 | Vite | 开发预览、构建桌面所需的静态资源 |
| 桌面容器 | Wails v2.15.0 | 嵌入静态资源，绑定受限的类型化方法；不把系统操作开放给页面 |
| 图标 | Lucide，按需使用 | 统一线性图标，不混用多个图标风格 |

选择原则：

- 业务代码以 `.ts` / `.tsx` 为主；不另外维护一份 JavaScript 业务实现。
- 使用普通 React 客户端，不引入 Next.js、服务端渲染或独立 Web 产品部署。
- 所需组件按需加入，避免整套模板、无关组件和第二套大型 UI 体系。
- shadcn/ui 是可修改的组件源码基础，不是业务系统、桌面容器或后端框架。
- 桌面宿主若需要 Go 文件，属于宿主 / 适配层，不要求 UI 开发承担后端实现。
- 初始化工程时锁定 React、Vite、Tailwind、组件基础依赖、Wails 和 Node 的具体兼容版本，提交依赖锁文件；不把本文的技术选型当成已安装依赖。

本轮锁定 Wails v2.15.0，依据已下载的该版本源码建立宿主与 production 构建入口；未使用 v3。锁定版本和通过源码编译都不代表平台运行时兼容性已通过验收。

## 3. UI 设计基调

### 3.1 定位

**克制、清晰、适合长期使用的桌面工作台。**

Anchor 是模型中转与管理工具，界面应优先帮助用户看清当前实例、配置和状态，不做聊天主界面，也不做带大幅宣传区域的营销页面。

**用户指定的视觉与布局基准是官方 [shadcn Blocks](https://ui.shadcn.com/blocks)，不是 Linear 风格，也不是仅使用 shadcn 按钮的自定义工作台。** 首个供应商切片使用 `sidebar-07` 的可折叠图标侧栏、SidebarProvider / SidebarInset、触发器与面包屑结构；内容替换为供应商表格、详情和表单，不复制无关的图表、账户、团队、项目或营销区域。

先选定并阅读官方 Block 与组件源码，再适配业务。保留其导航层级、灰阶主题、边框、间距和控件状态；不自行加入紫色 / 靛蓝品牌主操作、定制大侧栏或新的装饰体系。业务字段、中文文案、无障碍提示、状态色和 Mock 标识允许按 Anchor 约束适配。用户另行确认前，不把其他品牌分析当成主参考。

原型目前使用 Tailwind v3 / Radix。可使用官方 [v3 Blocks](https://v3.shadcn.com/blocks) 同名实现维持兼容，但须记录版本、来源、许可及本地改动；不得为追随示例顺手升级整套依赖，也不得把旧版源码称为最新实现。

设计原则：

1. 一套页面结构、一套组件规范、一套主题变量，覆盖两个目标系统。
2. 以表格、表单和详情面板为主，卡片用于分组，不把每个字段都包进卡片。
3. 灰阶承担大部分层级；主操作使用官方 neutral 黑 / 白主题，状态色另有明确语义。
4. 少渐变、少大阴影、不用玻璃背景；信息清楚优先于装饰。
5. 正文易读，不以过小字号换取信息密度。
6. 业务数据、加载状态、错误、离线和未实现功能必须明确区分。

### 3.2 主题与颜色

支持浅色、深色和跟随系统三种外观选择。首次默认跟随系统；用户手动选择后保留其偏好。界面不能只有一种主题完整、另一种只是反转颜色。

以下是本轮确定的 **shadcn neutral** 原型主题基线；不再沿用旧版 slate / 靛蓝色表。正文、控件和焦点组合仍须实测对比度。

| 语义角色 | 浅色 | 深色 |
| --- | --- | --- |
| 应用 / 内容背景 | `#FFFFFF` | `#0A0A0A` |
| 主要文字 | `#0A0A0A` | `#FAFAFA` |
| 次级表面 | `#F5F5F5` | `#262626` |
| 次要文字 | `#737373` | `#A3A3A3` |
| 普通分隔线 | `#E5E5E5` | `#262626` |
| 主操作 | `#171717` | `#FAFAFA` |
| 主操作上的文字 | `#FAFAFA` | `#171717` |
| 侧栏背景 | `#FAFAFA` | `#171717` |

颜色通过语义变量使用，如 `background`、`foreground`、`primary`、`muted`、`border`、`destructive`，不在页面中散落具体色值。主题变量与 shadcn/ui 的颜色角色保持对应。[来源：shadcn/ui 主题]

状态颜色分别表达成功、警告、失败和未知；不复用品牌色代替所有状态。普通分隔线不承担唯一的控件识别功能，输入边界和焦点标识需单独验证对比度。状态必须同时有文字或图标，不能只靠红绿区分。

### 3.3 字体、尺寸与密度

- 正文：系统无衬线字体栈；Windows 优先 Segoe UI / Microsoft YaHei，Linux 使用可用的系统字体和 Noto Sans CJK 回退。
- 等宽内容：模型 ID、技术标识和日志使用 `ui-monospace` 及平台回退字体；普通说明不使用等宽字体。
- 不依赖在线字体加载，不复制商业专有字体；若为统一中文字形打包开源字体，另行核对许可和包体成本。
- 正文与控件文字建议 14px、行高 20–22px；辅助文字 12–13px；页面标题 22–24px。
- 常规控件高 36–40px，图标按钮可点击区域至少 32px；默认表格行高 40–44px。
- 间距基于 4px：常用 8 / 12 / 16 / 24 / 32px；页面内容内边距建议 24px。
- 控件圆角约 6–8px，面板约 10–12px；优先细边框，弹出层才使用轻阴影。

以上均为 CSS 逻辑像素与初始建议；系统缩放、文字放大后必须保持可用，不能固定高度裁掉内容。

## 4. 页面结构与导航

### 4.1 应用骨架

```text
┌───────────┬──────────────────────────────────────────┐
│ Anchor    │ 页面标题 / 实例状态 / 最小化·最大化·关闭   │
│           ├──────────────────────────────────────────┤
│ 概览      │                                          │
│ 供应商    │ 表格、表单、详情面板或日志区域            │
│ 模型映射  │                                          │
│ Agent托管 │                                          │
│ 日志      │                                          │
│ 设置      │                                          │
└───────────┴──────────────────────────────────────────┘
```

- 左侧栏沿用官方 Sidebar 结构：桌面默认 16rem，折叠为 3rem 图标栏（inset 外侧间距另占 1rem）；小于 768px 使用受控移动抽屉，不用 CSS 隐藏文字代替交互。采用 inset 内容区，保留 SidebarTrigger 与 Ctrl / Cmd+B；移动抽屉应可关闭并管理焦点。
- 内容区头部持续显示当前实例的可读标识；实例选择控件只表达用户选择，不在本文规定连接方式。
- 页面操作靠近标题，每页至多一个主要操作，其余使用次级按钮或菜单。
- **2026-10-11 窗口外观修正：Windows / Linux 桌面宿主统一采用无系统标题栏窗口**，撤销“默认保留系统标题栏”的旧约定。直接将现有 inset 内容区 header 作为自定义顶栏，不在上方再叠加 Windows / GTK 原生标题栏或另一条装饰条；保持 sidebar-07 结构与 neutral 浅色 / 深色 / 跟随系统主题。
- 顶栏在工作区滚动时保持可见；空白与非交互文字区域可拖动，双击切换最大化 / 还原；右侧提供最小化、最大化 / 还原、关闭窗口，保留边缘缩放。按钮、链接、输入和窗口控制区明确排除拖动，控件有中文可访问名称、键盘焦点及足够点击面积。
- 窗口控制走前端窗口功能的 Model / Controller / View 与受限 Wails runtime 适配器，不增加任意系统命令、Go 业务接口或另一套业务规则；关闭只退出 GUI，不调用 StopCore。最大化状态读取必须有界，尺寸 / 焦点变化后刷新，不把点击当作操作成功。
- 浏览器原型不显示假可用的原生窗口控制。桌面模式缺 runtime 时禁用对应按钮并显示明确提示，不能模拟窗口已最小化 / 关闭。原生拖动、缩放、双击及窗口按钮的双平台验收仍单独记录；本轮沿用用户“不验收”要求。
- 列表、编辑和确认中持续显示操作对象，不能只在一次性通知中提示目标。

### 4.2 页面规划

| 页面 | UI 职责 | 首轮设计重点 |
| --- | --- | --- |
| 概览 | 展示当前实例与业务状态摘要 | 状态解释、待处理问题，不伪造统计值 |
| 供应商 | 列表、添加 / 编辑表单、状态说明 | 名称、协议、启用状态和脱敏凭据状态 |
| 模型映射 | 公开模型及候选映射的列表 / 详情 | 区分公开模型 ID 与上游模型 ID |
| Agent 托管 | 目标列表、计划预览、状态详情 | 区分已选择、已应用、冲突与实际请求证据 |
| 日志 | 可筛选、可复制的结构化展示 | 级别、时间、关联对象和长内容展开 |
| 设置 | 外观与界面偏好、版本信息 | 主题、导航和显示偏好，不混入未定连接配置 |

这是未来 UI 的页面规划，不表示现有后端支持全部页面。前端原型可展示未实现功能的禁用状态和说明，但不把模拟结果当真实成功，不默认增加 Skill 市场、自有 Agent 聊天或工作流页面。

## 5. 组件与交互规范

### 5.1 组件分层

- **基础组件**：由 shadcn/ui 按需引入，如 Button、Input、Select、Dialog、Alert Dialog、Tabs、Table、Tooltip。
- **公共业务外观组件**：PageHeader、StatusBadge、EmptyState、ErrorState、ConfirmAction、列表工具栏等。
- **页面组件**：组合前两层，表达供应商、模型映射等具体页面，不另外定义按钮与表单的视觉体系。
- 日志与大数据表是专用组合组件，不能因为引入基础 Table 就认为分页、筛选、性能和可访问性自动完成。

组件源码进入项目后由 Anchor 维护；更新上游时保留本地修改，逐项审查，不批量覆盖。[来源：shadcn/ui 简介]

### 5.2 表单、确认与反馈

- 表单字段有可见标签；说明与错误靠近字段，不能只用 placeholder。
- 简单编辑使用弹窗，复杂配置使用独立详情区域；避免多层弹窗嵌套。
- 输入校验只负责前端可判定的格式与必填提示，不替代后端业务判断。
- 未保存内容在离开、切换对象或关闭编辑面板时给出明确提示。
- 提交中显示进度并防止误点；前端禁止重复点击不等于后端已经具备幂等保证。
- 有风险的动作使用写明目标、对象和影响的确认界面；取消是安全默认选择。
- 每个页面覆盖首次加载、空数据、正常数据、错误和不可用状态；不要用无限转圈代替错误说明。
- 无能力返回、未实现、离线和结果未知使用不同文案，不一律显示“失败”。
- Toast 仅作短反馈；重要错误、冲突和需要处理的事项保留在页面内。
- 日志视图限制内存中的可见 / 保留行数，必要时虚拟化；更新不能无限增加 DOM，不在本文约定日志来源协议。

### 5.3 键盘与可访问性

- 所有可操作控件支持键盘访问，有清晰焦点，不以 hover 作为唯一入口。
- 弹窗管理焦点、关闭后回到触发控件；输入法组合输入期间不能误触发保存等快捷键。
- 图标按钮有可访问名称；表格保留语义、表头和可操作列说明。
- 普通正文对比度目标不低于 4.5:1，必要控件边界 / 状态图形目标不低于 3:1；实际原型需检测。[来源：WCAG 对比度]
- 支持减少动态效果的系统偏好，不使用持续闪烁、夸张动画或大量自动移动内容。
- 短过渡建议 120–180ms；不为表现“高级感”延迟实际反馈。

## 6. 前端工程组织

前端使用独立的 `desktop/frontend`，宿主在 `cmd/anchor-desktop` 与 `internal/desktop`；不把界面文件混进核心业务目录。以下为主要前端组织：

```text
desktop/frontend/
  src/
    app/                # 应用骨架、导航与主题入口
    pages/              # 各业务页面
    components/ui/      # 引入并维护的基础组件
    components/shared/  # 公共业务外观组件
    desktop/            # 生成契约、受控传输与会话 hook
    features/           # 按业务功能组织前端 Model / Controller / View
    styles/             # 主题变量和全局样式
    lib/                # 纯前端工具
    assets/             # 本地图标、字体等静态资源
  package.json
  package-lock.json     # 精确锁定依赖
```

### 6.1 前端功能模块 MVC

MVC 仅用于前端，不要求后端改造成 MVC。Model 是前端业务数据层，不是数据库，也不只是“模型映射”中的模型。每个功能可在 `features/<业务功能>/` 下组织：

| 层 | 职责 | 组织建议 |
| --- | --- | --- |
| Model | 数据类型、查询 / 更新、转换，服务端状态的统一来源 | `provider.model.ts`，通过传输适配器访问类型化桌面接口 |
| Controller | 加载、表单校验与提交、确认、刷新、错误及冲突流程 | `useProviderController.ts`，优先 hooks，不强制 class |
| View | 页面和表单展示、用户事件、加载与错误反馈 | `ProviderPage.tsx`、`ProviderForm.tsx`；不直接访问后端 |

依赖方向为 View → Controller → Model → 传输适配器；Wails 生成绑定集中在传输边界，不散落于组件或 Controller。`pages/` 负责页面装配，公共基础 / 外观组件无需各建一套 MVC，也不为每个按钮创建控制器。

同一服务端数据只保留一个权威来源；未提交表单草稿与已保存数据分开，避免在三层复制列表或派生状态。组件可保留焦点、弹窗开关等局部视觉状态，不要求所有交互都经过 Controller。Controller 按业务拆分，不演变为全应用状态容器。

前端格式校验不替代核心校验。编辑携带 revision，冲突提示重新读取或比较，不静默覆盖；写入超时且结果未知时不盲目重试。切换实例后隔离缓存并丢弃旧异步结果，不能将旧实例表单提交到新实例。Agent 操作保留计划审核、明确确认与恢复反馈，配置保存不等于上游已验证。

### 6.2 工程与文档约束

- 前后端多 agent 并行开发遵循[契约协作 skill](../../.agents/skills/anchor-contract-collaboration/SKILL.md)：主 agent 确定最小契约和共同基线，双方按独立文件范围实现；共享类型、样例与生成文件由指定负责人维护，变更统一同步，集成后以真实调用链验收而非只看 Mock。当前共享契约、生成命令和四层验证边界见[桌面运行契约](desktop-runtime.md)；读取协作规则不自动启动多个 agent。

- 当前已有供应商 Mock / desktop 两种模式、Wails 宿主与真实适配器。前端 `npm run build` 生成 desktop 静态资源，由 Go embed 随程序携带；打包见[桌面开发版构建](../release/desktop.md)。浏览器预览不是桌面启动入口。
- 局部交互状态优先留在组件内；只共享导航、外观等确实跨页面的状态，暂不引入复杂全局状态框架。
- 页面不直接处理系统命令、管理凭据或连接策略；供应商密钥不写入前端持久化缓存，提交成功、取消或卸载时清空，提交开始即清空表单密钥，失败需重新输入。具体语义见[供应商接口](provider-interface.md)。
- 文案集中管理，首轮以中文界面为主，结构上允许未来增加语言，不承诺本轮多语言交付。
- 离线也能加载界面骨架；静态资源随应用分发，不依赖 CDN 才能显示按钮或字体。
- 通过 TypeScript、ESLint、Vitest、Playwright 以及 Go 真核心集成测试分层验证；两平台原生 Wails 实测仍为独立门禁，不能用 Chromium 替代。
- 修改技术栈、MVC 边界、视觉 / 交互或平台基线时同步本文；接口变化同步对接契约与类型 / 测试；用户可操作功能同时核对 CLI 覆盖。设计、实现和实际验证分开记录，不以任务日志替代当前规范。

## 7. Linux / Windows 跨平台支持

### 7.1 复用策略

**一套主要 React UI 源码，两端分别打包、适配与验收。**

页面、主题、图标、组件和主要交互不分叉为 Linux / Windows 两套实现。系统窗口、运行时、打包依赖和字体差异允许适配，但不借此另建一套 UI。

Wails 使用平台渲染引擎：Windows 依赖 WebView2，Linux 需要 GTK / WebKit 相关依赖。跨平台不等于渲染完全相同，也不等于 Linux 无图形环境可以打开桌面应用。[来源：Wails 简介]、[来源：Wails 安装]

无图形服务器继续使用无头核心 / CLI；桌面端需要正常桌面环境。Windows 与 Linux 都必须满足 §1.1 的双击打开 GUI、自动启动／复用本机核心及关窗不停服行为；平台差异不降低功能要求，后台机制与真实宿主实现另行验收。

### 7.2 支持矩阵

| 平台 | 本文目标 | 实施与验收要求 |
| --- | --- | --- |
| Windows | 必须支持；首轮验证 Windows 11 x64 | 检查 WebView2 运行时，实测窗口、中文输入、缩放、主题和安装启动 |
| Linux | 必须支持；首轮验证 Ubuntu 24.04 LTS x64 | 明确 GTK / WebKit 运行时依赖，分别记录 X11 / Wayland 实测结果 |
| Windows 10 / 其他 Linux 发行版 | 兼容扩展候选，不提前承诺 | 结合安全维护状态、渲染引擎与依赖，单独决定和验收 |
| ARM64 | 后续候选，不是首轮交付承诺 | 工具链、依赖、安装包和真实设备分别验证 |
| macOS / Android / iOS | 不在本轮范围 | 不为潜在平台扩大当前 UI 与测试工作 |

Windows 11 与 Ubuntu 24.04 是本设计建议的首轮测试基线，不是用户新增的硬性版本要求；版本范围待实际发行决策确认。Wails 官方支持列表不等于 Anchor 已验证的产品支持列表。[来源：Wails 安装]

### 7.3 窗口与缩放

以下使用内容区域的 CSS 逻辑像素，不把物理屏幕分辨率直接当布局断点：

- 初始窗口建议约 1200 × 800；最低可用内容区域目标约 900 × 600，最终按真实标题栏与工作区调整。
- 内容宽度 ≥ 1100px：完整侧栏，列表 / 详情可并排。
- 内容宽度 900–1099px：侧栏允许折叠，详情改为单区域或侧面板，减少次要列。
- 宽度更小时保持关键操作可达，通过折叠和局部滚动降级；不因此增加手机版导航产品。
- 表格可局部横向滚动，长 ID 支持查看 / 复制；不让整个窗口被长字段撑宽。
- 测试 100% / 125% / 150% / 200% 缩放，以及窗口最大化、恢复、跨显示器和文字放大。
- 避免要求固定高度才可见的底部按钮，弹窗在小工作区内允许内容滚动。

### 7.4 渲染引擎兼容

- 不能只在 Chrome 开发预览中验证；必须在两端真实 Wails 窗口检查表单、弹出层、滚动、输入法和焦点。
- 选择 Tailwind 主版本及 shadcn/ui 组件来源时，先验证目标 WebView 能力，不默认“最新组件在所有 Linux 上都可用”。
- Tailwind v4 依赖现代浏览器能力，官方列出 Safari 16.4+、Chrome 111+、Firefox 128+ 基线；Linux WebKitGTK 仍需按实际版本验证，不能把 Safari 版本号直接当 Linux 依赖版本。[来源：Tailwind 兼容性]
- 若目标引擎达不到所选版本要求，先明确最低运行时要求，或成套选择兼容的 Tailwind / 组件版本；不能只改颜色就宣称解决全部兼容问题。
- Wails v2 在 Ubuntu 24.04 等环境可能需要 WebKitGTK 4.1 依赖与对应构建标签；这是宿主构建约束，正式构建文档另行记录。[来源：Wails 安装]
- 两端的字体、滚动条和抗锯齿可以有自然差异；布局层级、控件状态、信息可读性和操作能力必须一致。
- 系统主题探测失效时保留可用默认外观和手动选择；剪贴板、外部链接等宿主能力失效时给出明确反馈，具体调用实现另议。

## 8. 实施顺序与验收

### 8.1 建议顺序

1. 搭建最小 Wails + React + TypeScript 窗口，先验证两个平台与目标 WebView 的兼容性。
2. 建立基础组件、主题变量、导航骨架和公共状态页面。
3. 用模拟数据实现供应商、模型映射等关键列表 / 表单，并清楚标注模拟状态。
4. 检查键盘、中文输入、长文本、小窗口、缩放及浅色 / 深色外观。
5. UI 原型稳定后，另写前后端对接契约，再接入真实能力。

不在接口尚未明确时把 SSH、认证或转发临时塞进前端，也不为了原型立即扩充无头核心。

### 8.2 完整桌面验收清单（原生门禁尚未完成）

| ID | 目标 |
| --- | --- |
| F01 | 同一套页面与组件源码分别构建、运行于 Linux / Windows |
| F02 | 目标机器具备运行时依赖后可启动，缺少依赖有明确说明 |
| F03 | 浅色、深色、跟随系统均可用；外观偏好保存正确 |
| F04 | 小窗口、长文本、中文输入和各档缩放下关键操作不被裁切 |
| F05 | 主要导航、表单、弹窗可用键盘操作，焦点和错误清楚 |
| F06 | 空数据、错误、离线、未实现和结果未知不会伪装成成功 |
| F07 | 基础组件与业务组件遵守统一主题，状态不只依赖颜色 |
| F08 | 静态界面不依赖在线字体 / CDN；日志和大列表不会无限增长 DOM |
| F09 | UI 不包含 SSH、隧道、持久凭据管理或核心业务实现 |

正式构建和浏览器 / 桌面集成测试遵守工作区资源保护要求：先检查资源，通过 resource-guard 受限执行重任务，一次只运行一个重构建 / 测试，并清理本任务创建的进程与临时数据。

### 8.3 供应商切片：原型与真实桌面模式（2026-10-11）

[供应商基础功能](providers-v1.md)覆盖目录、详情、新增／编辑、启停确认、密钥操作及错误／冲突／未知结果。`prototype` 显式使用内存 Mock；`desktop` 通过 Wails → Go client → 核心读写，缺绑定失败关闭，不降级到 Mock。启动、连接来源、断开与显式停服使用真实会话状态。

保留官方 Blocks `sidebar-07` 与 neutral 主题；初版 slate / 靛蓝不是当前设计依据。来源见[源码记录](../../desktop/frontend/SHADCN_SOURCES.md)。既有设计帧仍为合成 Mock 画面，不能证明原生桌面验收。

此前宿主实现轮的 Go 全包 race 与 vet、共享契约漂移和真实隔离核心生命周期测试已通过；当时前端 TypeScript、lint、50 项单元测试、15 项原型浏览器测试与 6 项模拟桌面绑定浏览器测试已通过。后者不等于真实 Wails JS 绑定或 WebKitGTK / WebView2 通过。本轮安装包任务按用户要求不重跑测试、不做原生或安装验收；实际构建结果与剩余平台门禁见[桌面构建说明](../release/desktop.md)及对应任务记录。

### 8.4 供应商第一优先工作台（desktop.11）

六项需求已落地：供应商删除/复制/改名、模型映射与推理测试、独立 Key 状态与冷却/熔断、多 Key 和策略、三协议选择与核心转换、累计用量及价格估算。范围见[供应商路线图](provider-roadmap.md)，实际布局、MVC 文件归属、空/加载/错误/冲突处理和数据边界见[实现契约](provider-priority-one.md)。

详情顶部操作栏，下方上游目录及三个页签「密钥与状态」「模型与测试」「用量」；沿用 neutral 与响应式单列。危险动作明确确认；Key 输入在提交/取消/离开密钥页签时清空，功能写入时锁定切换和基础编辑，未知结果须刷新。价格只显示已知用量的当前价估算，测试和目录结果分开，不显示虚构的余额/健康。

本轮前端类型检查和55项定向单元测试、Go 共享契约漂移及隔离桥接检查通过；不运行浏览器套件或原生窗口验收。桌面构建与原生缺口分别记录，不沿用历史浏览器结果声称本轮新 UI 已做原生验收。

## 9. 当前结论与待定项

确定的技术方向：**React + TypeScript + shadcn/ui + Tailwind CSS 做 UI，Wails v2.15.0 承载 Linux / Windows 桌面窗口，维护一套主要界面。** 前后端职责分离、前端功能模块 MVC、共享契约和本机供应商真实调用链已经落地，不要求核心改造成 MVC。

当前开发版源码已实现安全初始化／启动／核验复用与单独确认停服；Windows 当前用户安装器和 Ubuntu24.04 AMD64 `.deb` 的打包入口、应用菜单／快捷方式及运行时依赖处理已补齐，构建目标与实际产物见[桌面安装说明](../release/desktop.md)。本轮按用户要求不做验收，两端安装／更新／卸载、原生启动与关窗存活、真实输入法／缩放仍未验证；托盘、静默自动升级及开机自启动设置未实现；手动在线更新（检查／下载校验／确认后交接系统安装器）已在当前源码接入设置页，已在 desktop.9 起打包，原生安装尚未验收，见[在线更新](online-updates.md)。公开 alpha.6 包不含本轮桌面能力，不能把源码实现和本地打包写成已验证安装即用。

设置导航开放“在线更新”，不改变 sidebar-07/neutral 视觉。updates 功能目录包含 Model（类型验证／数据访问）、hook Controller（阶段／同步 latch／过期结果隔离）和 View（渠道、检查／下载、错误与停服安装确认）。Settings 在核心离线时仍可进入，不将不可用状态伪装为“最新版本”。忙碌时锁定导航与提交；下载没有真实百分比时只显示不定进度，不编造速率。

来源 URL、文件路径和安装执行仅由 Go 宿主决定；JS 不能提交安装命令、下载源或目标文件。UpdateStatus/CheckUpdate/DownloadUpdate/InstallUpdate 的共享 DTO、样例、校验和错误说明见[在线更新契约](online-updates.md)。prototype 仅显示预览不可用提示，不能产生假检查／假安装；真实模式缺绑定失败关闭。installing 表示交接安装器，不表示已安装。只手动检查、不定时下载或后台停服；Linux 系统包安装授权不由前端代行。公开版本及旧开发安装包不含该入口，原生 Windows/Linux 验收需分别记录。
