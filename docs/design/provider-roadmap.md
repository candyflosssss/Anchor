## 第一优先：本轮全部实现

### 1. 删除、复制、改名

- [x] 供应商删除，并处理引用、已存密钥和正在使用的数据快照；不能静默破坏模型引用。
- [x] 供应商复制，明确复制范围和密钥处理。
- [x] 供应商改名，明确 ID 与引用迁移行为。
- [x] 模型删除，明确已有绑定的引用约束。
- 同组竞品能力线索：渠道复制、拖拽排序、配置导入导出；保留在本组需求记录中，不能因拆分实施而丢失。
- CLI 和 GUI 共用后端规则；破坏性操作明确确认，使用 revision 防止覆盖并发变更。

### 2. 连通测试和拉取模型列表

- [x] 手动读取已存供应商的模型目录，展示模型 ID、HTTP 状态、耗时与错误分类（desktop.10）。
- [x] 选择或填写模型，显式发起最小推理请求，展示状态码、耗时和错误类型。
- [x] 从上游目录选择模型并导入 Anchor 模型映射，避免手写 ID；处理别名冲突，不猜测工具等能力。
- 测试结果绑定具体供应商配置及密钥，明确实际请求时间，不把保存成功或目录成功显示为推理健康。

### 3. 记住失败，自动冷却和熔断

- [x] 429 按 Retry-After 暂停调度；无效或缺失值有明确默认值与上限。
- [x] 401/403 标记密钥失效，配置更新或显式恢复后才能再次使用。
- [x] 连续失败达到阈值后熔断；冷却后只放行一次探测，成功恢复。
- [x] DNS、连接拒绝、TLS 握手等确认请求未送达上游的失败允许换下一候选。
- 已发送后结果未知或已经开始返回输出的请求不得盲目重放。健康状态由真实结果更新；重启后的状态语义须明确。

### 4. 一个供应商配多个 Key

- [x] 多密钥增删改、启停与只入不出的秘密处理，兼容旧单密钥配置。
- [x] 轮流使用或优先使用一个可用密钥的选择策略。
- [x] 各密钥独立状态、冷却和测试结果，失败密钥自动跳过。
- 不回显密钥、不用完整密钥做 ID、不在日志或用量记录中保存秘密。

### 5. 协议转换：Chat Completions 与 Anthropic Messages

- [x] 在 Responses 之外接入 Chat Completions 与 Anthropic Messages 供应商。
- [x] 对应网关入口与转换，覆盖非流式、流式、工具调用及用量；不支持的参数或能力明确拒绝，不静默丢弃。
- [x] CLI、模型能力校验和供应商界面同步协议选择。
- 此项属于第一优先，不能只做 UI 选项就标记完成；也不等于已实现 Claude Code 配置托管适配器。

### 6. 用量采集

- [x] 从普通响应和流式最终事件采集 token 用量，包括可用的缓存 token 数据。
- [x] 按供应商和模型统计请求数、token、缓存命中、延迟和失败率。
- [x] 提供 CLI 查询及 GUI 查看；缺失用量标为未知，不伪造为已知零值。
- [x] 自定义单价估算费用，以及 models.dev 价格导入（原讨论同组能力线索）；明确币种与价格来源，不把估价当成上游账单。
- 只保留必要统计，不保存提示词、响应正文或密钥。

## 第二优先：后续范围

1. **会话固定和权重**：同一会话尽量固定供应商，减少缓存失效；支持优先级分组和组内权重。
2. **每个供应商单独设置代理**：显式 HTTP/SOCKS5 配置，维持不隐式读取系统代理环境变量的边界。
3. **改请求头和请求参数**：受限白名单；禁止覆盖 Authorization 等认证头，明确 service_tier 等参数的支持范围。
4. **不同认证方式**：按协议需要接入 Bearer、x-api-key、Azure api-key 等；第一优先协议转换必需的认证随对应协议实现。
5. **余额和额度查询**：优先考虑 OpenRouter、DeepSeek 及 new-api/one-api 等标准接口，不能从推理成功推断余额。
6. **供应商预设与配置导入**：降低填写门槛，明确导入格式、密钥处理及冲突行为。

## 不纳入本轮或必须先确定方向

- 用户、分组、计费、充值、支付：Anchor 定位为本机 Agent 工具，本轮不做多人分发平台。
- 用订阅账号转 API、OAuth 账号池：需另行确定产品与授权边界，本清单不构成实施授权。
- MCP、Skills、提示词、会话浏览、云同步：不属于本轮供应商功能。
- 图片、音频、向量、Realtime：本轮不实现。

## 原讨论中的竞品线索

以下是用户提供的先前讨论摘要，用于保留需求动机，未在本次文档补存中重新核验版本或当前支持范围，不作为已经完成的外部调研结论：

- new-api：渠道复制、一键测试、模型拉取、故障停用、优先级与权重、请求参数覆盖。
- cc-switch：排序、导入导出、健康与熔断、供应商额度展示、预设、按价格估算费用及 models.dev 线索。
- CPA、sub2api、CCS：多账号／多 Key 调度、失败账号跳过、轮流使用或优先使用一个；sub2api 的粘性会话及账号代理。
- Chat Completions / Anthropic Messages 兼容与用量可视化是本轮功能动机；竞品具体版本、数量和服务条款判断需后续单独核实。
