# 供应商第一优先实现契约

日期：2026-10-11。范围：供应商管理、多密钥、推理测试、模型映射、三协议与用量。

供应商列表展示健康与行内操作，点击进入整页详情（2026-10-11 起取代右侧详情栏）；编辑表单增加协议。详情增加操作栏、密钥卡片（启停、恢复、删除、轮询策略）、模型映射与显式测试、用量表。保留中性配色及窄屏单列。密钥输入在提交/取消时清空；结果未知时先重读。原型与桌面能力明确隔离。

管理操作经 `ProviderAction` → typed client → `POST /control/v1/providers/{id}/action`；读取详情经 `ProviderWorkspace` → GET workspace。操作白名单：delete/copy/rename/key-put/key-delete/key-reset/strategy/test/model-put/model-delete/price-put/price-import。输入固定 DTO，不接受任意 URL、shell 或 SQL。所有操作核对供应商 revision，模型操作另核对模型 revision。删除/改名/清除密钥要求 approved=true。复制默认不含密钥，显式 copy_keys 才复制。改名在一个事务里迁移模型候选和密钥；已在途请求使用原快照。删除供应商在同一事务清理其模型来源和价格，保留其他供应商的同名模型、顺序及元数据；存续模型 revision 加一，无候选时才删除公开模型。若将移除已启用 Binding 默认模型的最后一个候选，返回 referenced 并整体回滚；不隐式修改 Binding。映射创建显式声明工具/流式能力。

每 Key 具有稳定的用户指定 ID，秘密只入不出；旧 secret 迁移为 default Key。无 Key 的供应商可匿名调用；存在 Key 但全部停用时不退回匿名。在可用 Key 中轮询或按优先顺序选择。2026-10-21 当前源码按错误分数与窗口累计，达到阈值后仅对应 Key 硬冷却；默认阈值100、窗口300秒、冷却300秒。401/403加100、429加50、408／网络／5xx加25分；429和瞬时错误最多保留60秒。成功不清分，CD到期直接恢复；全部冷却时返回不可用。设置及迁移见[供应商接口](provider-interface.md#key-错误分数与冷却设置)。状态保存在核心内存，配置 revision 变化或核心重启后重置；显式恢复也可重置。统计持久化，绝不保存提示词、正文或 Key。

推理测试固定发送短文本、至多16输出 token，指定已保存供应商及 Key、模型；它是明确用户动作，可能产生少量用量。目录请求仍只读。测试返回供应商 revision、Key ID、时间、状态码、耗时和固定错误分类，不回显上游错误正文。测试固定使用指定 Key 供用户诊断，不因冷却换目标，保留并发限制。 最小测试接受 Responses 的 `reasoning` 项，包含达到16 token额度、尚无可见文本的 `incomplete` 结果；成功只证明本次最小请求可执行，不保证完整答案。推理项仅在测试校验中跳过，跨协议转换仍明确拒绝，避免丢失语义。2026-10-13 当前源码修复（未发布）：文本项的 `logprobs`、非空 `annotations` 不再因复用转换校验而导致测试失败；保留文本类型和元数据容器检查，跨协议转换边界不变。失败日志增加固定的 `evidence.validation_reason`，详细口径见[日志设计](logging.md)，不记录正文或原始解析错误。

协议：responses、chat-completions、anthropic。同协议尽量保留数据；跨协议仅转换明确支持的文本、函数工具、工具结果、流式事件与用量。不能转换的字段/内容显式拒绝，不静默抹除。服务端状态、后台任务、图片音频等不在本轮范围。网关接受三种入口；Messages 使用 x-api-key 也可鉴权。上游认证由协议确定，Anthropic 使用 x-api-key 和 anthropic-version。

用量以供应商/公共模型聚合：尝试次数、失败数、总耗时、已知用量次数、输入/输出/缓存 token。缺失用量单独计数；累计 token 仅代表已知部分。客户端断开和不完整流不会记为成功。UI 与 CLI 使用同一聚合查询。

## UI 与交互

详情为整页视图，沿用 neutral 主题，窄屏单列。顶部提供改名、复制、删除；下面分成「概况」「Key」「模型」「用量」页签，上游目录查询并入「模型」页签。密钥卡片展示可调度、冷却中、已停用及最近一次实际测试；冷却状态不可调度，展示错误分数和恢复时间；不能用目录成功代替健康。模型表单支持目录 datalist、手动 ID、公共别名和明确的工具/流式声明。用量页有逐模型统计及价格表单。

`provider-features.model.ts` 负责工作台 DTO 校验和动作构造，`use-provider-features.ts` 负责加载、同步写锁、过期结果丢弃、冲突/未知结果重读；两个 View 负责工作台和价格表单。既有列表 Controller 统一协调选择、编辑和目录请求。新增桥接只有固定的 ProviderWorkspace/ProviderAction，没有任意网络或系统执行能力。Go/TS 与 Mock 共用 `desktop/contract/provider-workspace.json`，原型记录全部为合成数据。

## 统计、价格与边界

统计请求数实际为上游尝试次数，包括失败、换 Key 重试和显式测试；测试以 `test:<上游模型>` 单列。平均耗时包含完整流读取时间；未知用量不能按零收费。缓存读取/写入 token 纳入总输入。无日期筛选、账单结算或原始请求存储。

价格单位为 USD / 百万 token。可为供应商下的公开模型配置输入、输出、缓存读取、缓存写入价格；输入/输出必填且允许0，缓存空白表示未知。models.dev 读取固定公开目录、精确选择供应商和上游模型，只预填表单；保存须再次显式提交。目录导入有8秒/16MiB限制，不携带供应商密钥。价格保留来源及更新时间。估算按**当前价格重算已知累计用量**，未知用量排除；已发生缓存用量但缓存单价未知时整个估价为未知。估价不是上游账单，不追溯历史单价。

Responses 同协议保持原有受限透传；Chat/Anthropic 入口先规范化为无状态文本/函数子集，再按所选 Key / 实际模型协议转换。并行函数调用与工具结果保留 ID；跨协议不支持图片、音频、推理块、引用注解、custom/托管工具、服务端会话及无法表达的参数。转换失败明确返回错误；转换流已开始时输出错误事件，不返回伪造的成功完成。Chat SSE 以 [DONE]、Responses 以完成事件、Anthropic 以 message_stop 判断完整结束；EOF 不算成功。转换到 Anthropic 时首内容块即时输出，后续并行块缓冲到完成以保持块顺序；缺最终用量则报错。事件上限2MiB，转换累计16MiB、256项。没有 Claude Code 配置托管适配器，也不宣称所有 Agent 特性兼容。

## 迁移与验证

SQLite schema 2 自动迁移到3，再迁移到4，全部已有 Key 继承所属供应商的旧协议。旧非空 secret 转为 default Key，原凭据和配置保留。基础供应商编辑只保留/替换/清除 default Key，其他命名 Key 由工作台管理；has_secret 表示存在任意已存 Key。历史用量保留旧供应商 ID，不随改名迁移，删除后仍可从 `usage` 查询。复制默认停用、复制配置与策略，默认不含 Key，不复制映射/价格/历史用量。模型删除只移除当前供应商候选与对应价格；最后一个候选才删除公开模型并触发 Binding 引用保护，不隐式改 Binding。旧程序不能打开已升级到 schema4 的数据库，不提供数据库降级。

第一优先六项的基线验证限定为状态迁移与引用保护、多 Key/冷却/半开、协议 JSON/SSE/错误处理、隔离真实桌面桥接、生成契约漂移，以及前端类型检查和55项单元测试。只用隔离状态与回环上游；未请求真实付费供应商，未查询线上 models.dev，未改真实 Agent 配置。安装包编译结果和具体交付记录见桌面构建文档，不重复运行旧包验收。

## Key / 模型协议增量（2026-10-11，本轮仅修改源码）

供应商不再统一决定已有 Key 的协议。每个 Key 有默认协议，实际模型名可在该 Key 下单独覆盖；未设置时动态继承。网关每次尝试、切换 Key 重试和显式推理测试都重新解析，路径、认证、JSON/SSE 使用同一结果。模型目录可明确选择 Key，认证只使用它的默认协议，不修改健康、覆盖或映射。公开别名映射和 Key 调度范围沿用现有规则。

页面在 Key 编辑内设置默认值；模型页选择 Key 后获取实际目录，并逐模型选择继承或三协议之一。已有覆盖即使不在本次目录中也显示。新 Key 默认 responses；旧 Key 迁移保留旧供应商协议。基础编辑替换 default Key 凭据保留它的协议，复制凭据同时复制协议覆盖，删除 Key 清理覆盖及对应模型来源；共享列表保留其他 Key，候选无来源时删除该候选，其他 Key／供应商的同名模型保留。最后一个已存 Key 被删除时也移除不限 Key 的候选，避免隐式转为匿名。若公开模型失去全部候选且仍是已启用 Binding 默认模型，整个删除事务回滚。CLI 和桌面共享动作及事务规则，见指令大全和供应商接口契约。

本次协议增量的定向验证结果见对应任务记录。本轮仅修改源码，未打包发布；安装包能力以各发行记录为准。


## 共享别名与倍率调度（2026-10-12）

供应商 model-put 的0模型版本可加入已有别名，保留共享能力和策略；重复加入同一供应商仍冲突。正版本只修改当前候选的上游及倍率，编辑共享能力/策略对所有候选生效。删除保留其他平台和价格、Binding，最后一个候选沿用引用保护。新增模型默认按倍率倒数加权轮询，旧模型仍按顺序；可在映射编辑切换策略。倍率手工输入0.01..1000，不查询站点价格。Key手动开关、冷却与并发共同决定可调度集合。CLI完整契约见指令大全 §5。

## 全部 Key 健康恢复（2026-10-30，源码未发布）

供应商列表／详情发现异常 Key 时提供「恢复所有 Key」，确认后复用 `ProviderAction` 的 `key-reset-all`。一次清除当前供应商全部已存 Key 在当前配置版本的失败计数、错误分数、冷却限制与测试记录，保留密钥、协议、enabled 与 revision；无 Key 为空操作，不影响其他供应商、不请求上游。冲突或结果未知先重读，不自动重放；上游凭据真正失效仍需更换。CLI 同能力及参数见[指令大全 §5](../cli/commands.md#5-供应商)，接口与显示条件见[供应商接口 §5](provider-interface.md#5-第一优先工作台desktop11)。未打包／原生验收。
