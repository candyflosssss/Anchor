# 日志可选显示内容

2026-10-12 已实现虚拟数据 UI。本文定义当前预览的字段和指标口径，不代表核心已经采集这些数据。

请求日志右上角“显示内容”打开字段面板，按类别勾选后立即生效。已选字段可上下移动，决定表格从左到右的顺序；至少保留一列，右侧详情入口始终可用。宽表在列表内横向滚动，详情入口固定在右侧；窄窗口的字段面板改为单列。

## 默认与预设

| 预设 | 显示顺序 |
| --- | --- |
| 常用 / 默认 | 时间、结果、模型名称、供应商、首字时间、总耗时、TPS、错误码 |
| 性能 | 时间、模型名称、供应商、思考深度、首字时间、总耗时、TPS、输入 Token、输出 Token |
| 排障 | 时间、结果、请求 ID、供应商、Key 标识、上游 HTTP、错误码、失败 / 结束阶段、尝试次数 |

预设应用后仍可自由勾选和排序，“恢复默认”恢复常用布局。系统日志暂沿用固定字段，不受请求列偏好影响。

共 27 个可选字段。字段注册表位于 `desktop/frontend/src/features/logs/log-columns.model.ts`；Controller 管理偏好和布局，View 按注册表渲染。

## 指标口径与缺失数据

这些定义是本次 Anchor UI 预览采用的口径，真实接入前须确认采集时点与上游用量字段，不宣称所有供应商采用相同定义。

- **首字时间**从根请求开始计时，包含首字之前的路由、重试和等待；首个网络包、角色事件或单独的思考事件不算正文。没有可靠正文写出时间就显示“未知”。
- **TPS**只在流式、完整观测正文生成区间、正文 Token 明确且为正、生成耗时有限且为正时计算。排除思考 Token、首字前等待和重试时间；不直接用“总输出 / 总耗时”。非流式、流式中断、只有思考或区间 / 用量缺失时显示“未知”。
- **思考深度**展示请求设置值，如 low、medium、high；明确未设置时显示“未指定”，没有快照时显示“未知”。不根据模型名或耗时推断，也不表示实际思考时长。
- **用量**缺失不补零。重试可能有未报告用量的尝试，表格对多次尝试的输入、输出、总 Token 标注“已知小计”，完整信息见尝试详情。缓存读取通常已包含在输入里，不重复加到总 Token。
- **HTTP / 错误码**没有 HTTP 响应显示“未收到”，没有错误码显示“—”。HTTP 200 可以与 Anchor 校验失败同时存在。没有上游派发的模型 / 供应商 / Key 显示“—”。

合成样例包含 584 ms 首字时间、1,200 ms 正文生成区间、326 个正文 Token，TPS 显示 271.7 t/s；只有思考的测试请求和中断流的 TPS 显示“未知”。它们用于界面验证，不是原始报错的真实排查证据。

## 偏好保存与接入边界

只将已选字段 ID 和顺序保存到本机 `localStorage` 的 `anchor.ui.logs.columns.v1`。偏好恢复会过滤旧字段、去重，空或损坏的配置回到默认；存储失败时当前页面仍可使用并提示刷新后可能重置。日志记录与保留设置继续只在内存模拟，刷新重置。

当前 prototype 与 desktop 均持续展示虚拟数据标记，没有新增后端 / 桌面 DTO 或真实日志读取。纯展示偏好不新增 CLI；未来真实日志查询、跟随、导出和保留管理仍需独立接口与 CLI 覆盖，见[日志设计](logging.md)。
