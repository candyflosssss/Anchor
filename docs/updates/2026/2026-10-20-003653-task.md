# 任务更新：供应商多 Key 原子创建与请求地址编辑

- 时间：2026-10-20T00:36:53+08:00
- 类型：task
- 状态：completed

## 摘要

新增供应商支持一次保存多个 Key 与多个请求地址；保留既有地址编辑能力并验证编辑不丢失 Key。本轮仅源码更新，未重新打包或发布。

## 具体更新

- 新增供应商表单保留可选默认 Key，并可增删命名 Key，每个 Key 独立选择请求渠道；支持仅命名 Key、多 HTTPS 域名／IP／端口地址。HTTP 仍仅允许数值回环地址。
- Model 校验重复／保留名称、协议、秘密长度与内容；Controller 一次 SaveProvider 提交全部 Key，立即清空草稿秘密并在结束时清理请求快照，未知结果不自动重放。编辑供应商不发送创建 Key 草稿，继续使用既有 Key 管理入口。
- 增加 create-only initial_keys 可选输入，经生成的桌面 DTO、桥接、类型化客户端与核心，在同一数据库事务创建供应商及全部 Key；任一失败全部回滚，成功仅推进一次 revision。旧单 Key 请求兼容，不修改数据库 schema。
- 修正供应商列表／单项读取 has_secret 仅统计 default 的偏差，只有命名 Key 时也正确返回 true，不输出秘密。
- 增加共享合成样例、前后端与 CLI 回归测试，覆盖多地址编辑保留 Key、独立协议、CAS、事务回滚与取消／未知结果秘密清理；同步接口、前端、CLI 帮助／大全／历史及批量 CLI 缺口说明。
- 全包验证发现既有 NewAPI 客户端测试 fixture 未处理公开 /api/status 元数据请求；仅补齐 fixture 并断言无用户授权，不改生产 NewAPI 逻辑。
- 仅纳入当前任务的 27 个文件／相关 hunks；系统代理、日志与刷新等其他任务改动及本地依赖缓存不随本次提交。
